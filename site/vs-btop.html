gander vs btop

Both reject htop's layout. They disagree about what should replace it: btop draws the machine, gander lists the processes.

Pick btop when the question is "how is this machine doing". Pick gander when the question is "which process is doing it" — or when you want the answer to that question in a script.

Different tools that look like the same category

btop is a resource monitor: CPU, memory, network, disk and temperature as graphs and braille plots, with the process list as one box among several. It is good at what it does, and if you want a dashboard it is the right answer.

gander does not try to be a dashboard. It is a process list — the same thing htop is — with the detail of the selected process moved from a separate screen into a column. The screenshots are the honest summary:

btop's platform list is genuinely broader in one direction — it also builds for NetBSD and OpenBSD, which gander does not. If those are your systems, btop is the choice and this page is not for you.

The scripting difference is the practical one

btop is a screen. There is no supported way to ask it for a machine-readable snapshot, so anything automated has to either scrape the display or read /proc itself.

gander's batch mode is the same binary with the TUI turned off:

gander --json --limit 10                   # one JSON sample, top 10 rows
gander --sort PERCENT_MEM --limit 20       # heaviest 20 by memory
gander -F "python|node" -n 5               # five samples, filtered

That is not a feature you use every day. It is the difference between a tool you look at and a tool you can put in a cron job.

Install

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # any platform with Rust

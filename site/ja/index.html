gander0.6.7

Rust で書かれた、Linux・macOS・FreeBSD 向けのクロスプラットフォーム対話型プロセスビューアです。

htop と同じプロセスデータを読み、htop のキーバインドを引き継ぎ、選択中のプロセスの詳細を一覧の横に置きます。htop は詳細を別画面に置きます。

ダウンロード GitHub のソースコード インストール

できること

gander はシステム上で何が動いていて、どれだけリソースを使っているかを表示します。Linux・macOS・FreeBSD で動作し、htop のキーバインドの多くを引き継ぐので、指に覚えがあるキーはそのまま使えます。

詳細パネルはカーソルに追従する

行を選ぶと右のパネルに情報が入ります。コマンドライン、状態、メモリ、実行時間、ユーザー、スレッドです。

サンプリングは描画経路の外にある

サンプリングはバックグラウンドスレッドが行い、描画側はスナップショットを読みます。マシンが高負荷でもテーブルはカクつきません。負荷が上がるのは、まさに画面を見ているときです。

htop の設定はそのまま持ち込める

--import-htoprc が既存の htoprc を読み込み、--save で gander 独自の TOML として書き出します。調整した列とソート順は切り替え後も残ります。

TUI なしでスクリプトから使える

--json、-n、--sort、--filter、--limit はプロセスの行を出力して終了します。curses 画面をパースする必要はありません。フィールドと jq の例はバッチモードのページにあります。

Linux ではさらに多くの情報を扱える

PSS/EPSS、PSI、zram/zswap、GPU、遅延統計、コンテナ識別情報はオプションの列やヘッダーメーターで、/proc と /sys から読み取ります。

ncurses のインストールは不要

描画は ratatui と crossterm によるものです。ビルド前に開発ヘッダを入れる必要も、ターミナルライブラリをリンクする必要もありません。

同じマシンを見る 3 つの方法

panels — デフォルト 画像をフルサイズで表示(新しいタブ)
t — プロセスツリー 画像をフルサイズで表示(新しいタブ)
L — htop レイアウト 画像をフルサイズで表示(新しいタブ)

「—」は「そもそも適用対象がない」という意味です。htop は定義上、htop 自身のキーバインドを持ち、自身の設定を読みます。

日常的に差が出るのは選択プロセスの行です。htop、btop、bottom は「今何が動いているか」に、すべてのプロセスを一度に並べて答えます。気になっているプロセスの詳細は別画面にあるか、そもそもありません。gander は詳細パネルをテーブルの隣に置くので、行を選んだ時点で答えがそこにあり、一覧から離れる必要はありません。

より長い比較は各ツールごとのページにあります:gander vs htop、gander vs btop、gander vs bottom。プラットフォーム固有の注記は macOS 向けと FreeBSD 向けにあります。

インストール

macOS(Homebrew)

brew install pandasir/tap/gander

Rust が入っている任意のプラットフォーム

cargo install gander-bin   # インストールされるコマンドは `gander`

Arch Linux

git clone https://github.com/pandasir/gander
cd gander/packaging/aur && makepkg -si

Debian、Ubuntu

curl -fsSL https://pandasir.github.io/gander/gander.gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/gander.gpg
echo "deb [signed-by=/usr/share/keyrings/gander.gpg] https://pandasir.github.io/gander stable main" \
  | sudo tee /etc/apt/sources.list.d/gander.list
sudo apt update && sudo apt install gander

Fedora、RHEL

sudo rpm --import https://pandasir.github.io/gander/RPM-GPG-KEY-gander
sudo curl -fsSL https://pandasir.github.io/gander/gander.repo \
  -o /etc/yum.repos.d/gander.repo
sudo dnf install gander

ビルド済みアーカイブ

すべての Release には .tar.gz アーカイブが付属します。macOS(Apple Silicon と Intel)、Linux(x86_64 と arm64、glibc と静的リンクの musl)、FreeBSD 向けで、それぞれに .sha256 ファイルがあります。GitHub Releases を参照してください。

ソースからビルド

Rust 1.89 以降が必要です。

git clone https://github.com/pandasir/gander
cd gander
cargo install --locked --path crates/bin

使い方

gander                                     # 対話型 TUI
gander --delay 500                         # 500 ミリ秒ごとにサンプリング
gander -n 5 -d 1000                        # テキスト形式で 5 回出力
gander --json --limit 10                   # JSON 形式で 1 回出力
gander --sort PERCENT_MEM --limit 20       # メモリ使用率の上位 20 件
gander -F "python|node"                    # コマンドラインで絞り込み
gander --import-htoprc ~/.config/htop/htoprc --save

フィルターは大文字と小文字を区別しない固定文字列で、| で区切ります。正規表現ではありません。すべてのオプションは gander --help で確認できます。

よくある質問

gander は htop の代わりになりますか？

はい、そして「いいえ」でもあります。同じ /proc を読み、キーも htop の位置にあるので、今の使い方はそのまま通ります。--import-htoprc で htop の設定をそのまま持ち込めます。ただし既定のレイアウトは意図的に htop と違います。「全幅の表 + 別画面の詳細」がプロセス一覧の読み方の唯一の正解ではないからです。

gander は Windows で動きますか？

動きません。バックエンドは /proc(Linux)、sysctl/Mach/libproc(macOS)、sysctl/libkvm(FreeBSD)の 3 つで、Windows 向けはありません。Linux のカーネルインターフェースに依存する列(PSS、PSI、zram、遅延統計、コンテナ)も Linux 専用です。

crates.io のパッケージ名が gander-bin なのはなぜですか？

crates.io の gander は無関係な、とうに yank されたクレートだからです。インストールされるコマンド名は gander のままです。

なぜ gander は ncurses を使わないのですか？

描画は ratatui と crossterm で行うので、ビルド前に ncurses の開発ヘッダを入れる必要はありません。

gander はスクリプトから使えますか？

使えます。gander --json、-n、--sort、--filter、--limit は TUI を起動せず、プロセスごとに 1 行を出力します。フィールドのリファレンスと jq の例は JSON プロセス一覧のページにあります。

gander のライセンスは何ですか？

GPL-2.0-or-later です。gander の動作、キーバインド、列の意味は htop から取っています。ライセンスの互換性を維持し、出典を明記してください。

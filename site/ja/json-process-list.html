スクリプトのための JSON プロセス一覧

TUI が表示する数値を、サンプルごとに 1 つの JSON ドキュメントとして。cron ジョブやモニター、そして今までは固定幅の ps 出力をパースしていたあらゆる場面のために。

一回きりの列出力には ps を。そこでは依然として ps が正解です。メモリ使用率、完全なコマンドライン、バイト単位のサイズをデータとして Linux・macOS・FreeBSD 上で得たいなら gander --json を。ライブの CPU 使用率には、同一呼び出しで 2 つ以上のサンプルを取ってください。最初のサンプルには CPU の基準がありません。

インストール ソース

他のツールがスクリプトにくれるもの

ps は空白で揃えた列のスナップショットを 1 つ出力します。あらゆるサーバーのスクリプトの半分に awk の呼び出しが潜っているのはこのせいで、列が改名された日に壊れます。CPU の数値はプロセスの生涯平均で、いま何をしているかではありません。切り詰められない comm と完全なコマンドラインの両方を取るには、procps と Darwin で違うフラグが必要です。

top にはバッチモード(-b)がありますが、バッチ化されるのは描画済みの curses 画面です。表示のテキスト採取であって、データではありません。htop にはバッチモードがまったくなく、何かのサンプルを 1 つ頼む方法もありません。btop も同じ立場で、bottom もそうです。

この不足があるから、シェルスクリプトは結局 /proc をプラットフォームごとに手で読み直すことになります。gander の TUI とバッチモードは同じバックエンドを読みます。Linux では /proc、macOS では sysctl/Mach/libproc、FreeBSD では sysctl/libkvm です。スクリプトが見る数値は、対話ビューが表示する数値と同じです。

バッチモード

gander --json                       # JSON を 1 回出力して終了
gander --json --limit 5             # 最大 5 行
gander --json --sort PERCENT_MEM    # TUI の F6 と同じソート
gander --json -F "postgres|nginx"    # 固定文字列フィルタ。正規表現ではない
gander -n 60 -d 1000 --json         # 60 サンプル、約 1 秒間隔

1 回の呼び出しがプロセス行の JSON 配列を 1 つ出力して終了します。-n N では N 個の配列を続けて出力します。ドキュメントのストリームなので、jq -s 'add' で 1 回の実行を 1 つのリストに平らにできます。ソートとフィルタは JSON 生成の前に行われるので、--limit 5 は 5 行を出力して止まります。全テーブルを作ってから削る、ということはしません。

cpu_percent には同じプロセスの 2 つの連続サンプルが必要です。呼び出しは毎回新しいサンプラーから始まるので、最初のサンプルでは全行の CPU が 0 になります。後から現れたプロセスも、以降のサンプルでは 0 から始まります。メモリの数値にこの基準は要りません。スクリプトや cron で CPU サンプルを取るには、1 秒間隔で 2 サンプル取って 2 つ目の配列だけを使います:

gander -n 2 -d 1000 --json | jq -s '.[1]'

jq で、メモリの上位 5 消費者をタブ区切りで:

gander --json --sort PERCENT_MEM --limit 5 |
  jq -r '.[] | [.pid, .mem_percent, .rss, .cmdline] | @tsv'

同じ行集合を 1 分間の実行で統合し、急に跳ねて消えるものを捉えます:

gander -n 60 -d 1000 --json | jq -s 'add |
  group_by(.comm) | map({comm: .[0].comm, max_rss: (map(.rss) | max)}) |
  sort_by(-.max_rss) | .[0:10]'

フィールド

実物の 1 行。macOS から:

{"pid":407,"ppid":1,"uid":0,"comm":"loginwindow","state":"S",
  "cpu_percent":0.00,"mem_percent":0.18,"rss":15613952,
  "vsize":446144643072,"nice":0,"priority":0,"threads":6,
  "elapsed":479475,"is_thread":false,"identity":407,
  "cmdline":"/System/Library/CoreServices/loginwindow.app/Contents/MacOS/loginwindow console",
  "memory":null}
フィールド意味
pid、ppid、uid各 ID。カーネルが報告するまま。
comm実行ファイルのベース名。TUI が既定でソートする列。
cmdline引数を含む完全なコマンドライン。決して切り詰めません。ps が手こずらせるフィールドです。
stateカーネルの状態文字。R は実行中、S はスリープ、Z はゾンビ、など。
cpu_percentこのプロセスの連続サンプル間の CPU 使用量。生涯平均ではありません。前のサンプルが得られるまで 0 で、呼び出しの最初のサンプルの全行も 0 です。
mem_percentサンプル時点での常駐メモリの総物理メモリに対する割合。最初のサンプルでも利用できます。
rss、vsize常駐サイズと仮想サイズ。バイト単位です。「KB、たぶん」ではありません。ps 出力のパースを信頼できなくする単位の曖昧さのことです。
nice、priority、threadsスケジューリングの数値。カーネルが報告するまま。
elapsedプロセス開始からの秒数。
is_threadその行がプロセスではなく別のプロセスのスレッドである場合に true。--threads を付けるとスレッドごとの行も出力されます。
identity数値の行識別子。プロセス行では PID、スレッド行ではスレッド固有の ID。macOS で PID を共有するスレッドを区別するためのもので、コンテナ識別子ではなく、常に存在します。
memoryプラットフォーム依存の、入れ子になったメモリとリソースの詳細。macOS と FreeBSD では null。Linux では、要求されなかった読み取りや取得できなかったデータの値が null になります。

ソートには TUI の列名を受け付けます。PERCENT_CPU、PERCENT_MEM、M_RESIDENT、PID など。これらは JSON のキーではありません。rss でソートするには --sort M_RESIDENT を使います。-F はコマンドラインに対して、大文字小文字を区別しない固定文字列を | で区切って照合します。意図的に正規表現にしていません。定期的に走るフィルタが、一文字の違いで全部にマッチする状態になってはいけないからです。

何ではないか

監視エージェントではありません。呼び出しごとに完結します。デーモンも、ストレージも、ダッシュボードも、依存もありません。cron ジョブはメモリのスナップショットのために gander --json をファイルに追記できます。CPU の計測には、代わりに上の 2 サンプルのコマンドを使ってください。ファイルは jq で読めるままです。保持とアラート付きの継続収集が必要なら、すでに走らせているツールをこの出力に向けてください。gander がサーバーを生やすことは期待しないでください。

ps でもありません。一回きりの列出力、プロセスグループの選択、セッション ID は ps の得意分野で、ps で動いているスクリプトが変わる理由はありません。バッチモードは、ps が追いつかない場面のためのものです。ライブの使用率、バイト単位のサイズ、そして対話ビューと一致する数値。

インストール

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # Rust の入った任意のプラットフォーム

Debian・Ubuntu・Fedora・RHEL の Linux パッケージは署名付きリポジトリにあります。リリースごとに macOS(Apple Silicon と Intel)、Linux(x86_64 と arm64)、FreeBSD のアーカイブも出します。すべてのインストール方法を見てください。

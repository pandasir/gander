gander / bottom との比較

gander vs bottom

3 つの比較の中でいちばん近い相手です。どちらも Rust 製、どちらも Linux・macOS・FreeBSD をカバーし、どちらも htop のレイアウトを拒みます。違うのは、画面を何のために使うかです。

bottom は自分で配置するウィジェットのダッシュボードをくれます。gander は htop のプロセス一覧に、詳細を同じ画面へ移したものをくれます。グラフと自由な設定を優先するなら bottom のほうが進んでいます。htop の指の感覚とスクリプトで使える出力を優先するなら gander です。

FreeBSD:「ビルドできる」は「対応している」ではない

bottom の README はこの点を明確にしています。公式プラットフォームは macOS、Linux、Windows。FreeBSD x86_64 は別のリストに現れ、次のような前置き付きです。

CI でビルドやテストが実行されていない可能性があります。安定版リリース前にメンテナーによる十分なテストが行われていない可能性があります。機能の欠落や修正されないバグなど、限定的なサポートしか受けられない場合があります。

bottom は自分自身の限界を正直に説明しています。それはこのプロジェクトも目指すところです。ただ、その意味は「FreeBSD は当てにできないプラットフォーム」ということです。

gander は sysctl と libkvm を読む専用の FreeBSD バックエンドを持ち、QEMU 上の FreeBSD 14 VM でテストスイート全体を実行する CI ジョブがあります。ゲスト内で ps(1)、sysctl(8)、swapinfo(8)、netstat(1) と数値を突き合わせます。FreeBSD に存在しない機能は、ぼかさずに一覧として示しています。コンテナ列なし、PSS なし、GPU 列なし、ディスク転送速度のメーターなし。htop on FreeBSD を参照してください。

FreeBSD を使っているなら、このページでいちばん具体的な違いはここです。

スクリプト:gander にはバッチモードがある

bottom にはスクリプトから呼べるものがありません。自動収集には /proc(または同等のもの)を自分で読みます。TUI と同じ整形で出力したくなるまでは、それで足ります。

gander のバッチモードは、インターフェースを切った同じバイナリです。スクリプトが受け取る数値は、画面に描かれたはずの数値と同じです。

gander --json --limit 10
gander --sort PERCENT_MEM --limit 20
gander -F "python|node" -n 5

終了ステータスにも意味があります。スキャンの失敗は空配列ではなく、非ゼロの終了コードで返ります。

htop から移る場合

2 つのうち htoprc を読めるのは gander だけです。htop で長年かけて調整した列とソート順があるなら、最初に気づく違いはここです。

gander --import-htoprc ~/.config/htop/htoprc --save

--save を付けなければインポートはドライランで、htoprc は決して変更されません。キーの違いは vs htop を参照してください。

インストール

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # Rust が入っている任意のプラットフォーム

署名付きの apt / dnf リポジトリと、x86_64-unknown-freebsd を含むアーカイブは、インストールの節にあります。

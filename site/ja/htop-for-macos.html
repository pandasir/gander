gander / macOS の場合

macOS でのプロセスビューア

htop は macOS で動きます。人がつまずくのは htop ではありません。Linux では当たり前だったいくつかの数値に macOS の対応物がなく、それでも表示するビューアは推測している、という点です。

このページは棚卸しです。macOS がプロセスビューアに教えてくれること、教えてくれないこと、そして gander がその不足ごとにどうしているか。htop と gander の両方に当てはまります。同じインターフェースを読んでいるからです。

gander をインストール バックエンドの詳細

macOS が渡してくれるもの

htop のプロセステーブルのほとんどは 3 つの源から来ていて、3 つとも macOS で機能します:

数値ソース
プロセス一覧proc_listallpids と PROC_PIDTASKALLINFO
コマンドラインsysctl(KERN_PROCARGS2)
実行ファイルのパスproc_pidpath
作業ディレクトリproc_pidinfo(PROC_PIDVNODEPATHINFO)
スレッドPROC_PIDLISTTHREADS + PROC_PIDTHREADINFO
メモリ合計、スワップhost_statistics64、hw.memsize、sysctl(vm.swapusage)
コアごとの CPUhost_processor_info
ネットワークスループットsysctl(NET_RT_IFLIST2)

つまり「htop は macOS では実質動かない」というよくある主張は間違いです。動きます。面白いのは 2 つ目の表です。

macOS が渡してくれないもの

ここにある行はどれも Linux 固有の仕組みで、Darwin には対応物がありません。

macOS 上の gander
プロセスごとの PSS / EPSS列ごと存在しません。- を表示するのではなく
PSI プレッシャーメーターメーターは n/a here と表示
Zram / Zswap / HugePagesメーターは n/a here と表示
コンテナ / cgroup の識別cgroup の概念がなく、列は対象外
CPU 遅延統計列は対象外
I/O 優先度(i)ioprio_set がなく、パネルがその旨を表示
GPU 列IOKit が必要。対象外
ホスト全体のディスクスループットメーターは n/a here と表示
CPU アフィニティ編集ヒントのみ

大事な区別は、「列が存在しない」ことと「列が - を表示する」ことの違いです。列の中の - は「このプロセスにはいま値がない」と読めます。存在しない列は「このシステムには概念がない」と読めます。macOS 上の gander は、これらの列を設定画面から丸ごと外し、メーターは n/a here のまま置いておきます。Linux で書いた設定ファイルを Mac でも読めなければならず、消えたメーターは誠実な設定ではなく壊れた設定になってしまうからです。

メモリ:バグだと思われがちな数値

macOS のメモリ会計は Linux のものとは別物で、片方をもう片方に対応させるビューアは目に見える幅度間違えます。vm_statistics64 は互いに重なる 2 つの計上系を公開しています。使い方によるもの(active、inactive、wire、compressor、free、speculative)と、裏付けストアによるもの(internal、external)です。系をまたいで合計すると二重計上になります。gander は裏付けストアの系に、そこで扱われない 2 つのページ種別を加えて数値を作ります:

used      = (internal - purgeable) + wired + compressed
available = total - used

出てくる数値は htop が印字するものと同じで、導き方も同じ。さらにアクティビティモニタと top の報告とも同じです。Mac の上では gander と htop は互いに一致します。一致しない相手は、vm_stat から素朴に total - free を計算したもののほうで、どちらのツールも間違って見えるのはその比較です。

inactive と speculative は使用済みではなくキャッシュとして数えます。1 週間起動し続けたマシンは、inactive が大きくてもメモリ不足ではありません。再利用可能だからです。

Mac の上で gander と htop が違うところ

数値は同じです。違うのは画面です。htop の詳細パネルは全画面モードです。e が環境変数、l が開いているファイル、s がシステムコールを担い、どれもプロセス一覧を置き換えます。戻るには場所を探し直すことになります。gander は選択中プロセスのコマンドライン、状態、メモリ、実行時間をテーブルの隣の一列に置くので、一覧は元の場所に留まります。

キーバインドは同じ、htoprc の取り込みも同じです。htop のレイアウトが欲しければ L で得られます。違うキーは vs htop のページを見てください。

macOS へのインストール

brew install pandasir/tap/gander

# または、Rust ツールチェーンがあれば
cargo install gander-bin

Apple Silicon と Intel 両方のビルド済みアーカイブも Release にあります。

macOS でのライブテストは実際のプロセステーブルを読むため、テストスイートは制限付きサンドボックスの外で実行する必要があるかもしれません。3 プラットフォームのバックエンド比較は docs/PORTABILITY.md にあります。

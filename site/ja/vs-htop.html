gander / htop との比較

gander vs htop

プロセスデータもキーバインドも同じです。違うのは、選択したプロセスの詳細の置き場所。テーブルの隣にあり、キーを押して別画面を呼び出す方式ではありません。

ディストリビューションに同梱されているツールだけで足りるなら htop を。htop のキーをすでに知っていて、テーブルを手放さずに詳細パネルも欲しいなら gander を。

インストール ソース

作業の仕方が変わる、たった一つの違い

htop は「今何が動いているか」に、すべてのプロセスを一度に並べて答えます。そして「このプロセスは何をしているのか」には別画面で答えます。旧バージョンの info パネル、新バージョンでは独立したビューです。いずれにせよ、読んでいる間はテーブルが消えます。

gander は両方を同時に画面に置きます。詳細パネルはテーブルの隣の列で、カーソルに追従します。一覧を下へ移動するたびに詳細が読み直され、プロセスごとにキーを押す必要はありません。広い端末では空き領域が働いてくれ、狭い端末では要素が重なるのではなく、レイアウトが幅に合わせて変わります。

htop の配置のほうが良ければ、L を押してください。全幅レイアウトは組み込みで、選択は記憶されます。

「—」は「そもそも適用対象がない」という意味です。htop は定義上、htop 自身のキーバインドを持ち、自身の設定を読みます。

この表の多くの行で基準になっているのは htop で、gander は列の意味とキーバインドを意図的に htop から取っています。gander が単なる「htop + パネル」ではない行は末尾の 3 行です。バッチモード、Linux 専用の追加列、そして htop に詳細パネル相当のものが存在しないという点。

設定をやり直さずに切り替える

htop の設定は htoprc に保存されます。gander はこのファイルを読み、そこから独自の TOML を書き出します。長年かけて調整した列とソート順が引き継がれます。

gander --import-htoprc ~/.config/htop/htoprc --save

--save を付けない場合、インポートはドライランになり、変更内容を表示するだけです。htoprc は変更されないので、htop は今までどおりに動作し続け、両者を並べて比較できます。

インポーターは htop の 1 起点の列 ID を処理します。素朴な変換が失敗するのはここです。gander に対応するものがない設定は、黙って捨てずに報告します。

キーバインドが違うところ

htop のファンクションバーにある操作は、htop が置いた場所のままです。違うのはこれらです。

Ihtop ではソート順を反転します。gander では選択中のヘッダーメーターの表示モードを切り替えます。ソートの変更は F6 / < > を使ってください。
Lpanels レイアウトと htop レイアウトを切り替えます。htop にはないキーです。
+ / -サンプリングを速く、または遅くします。
Shift+Left / Shift+Rightヘッダーメーターのカーソルを移動します。

バッチモードのフラグを含む全キーバインドは docs/KEYS.md にあります。

インストール

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # Rust が入っている任意のプラットフォーム

Debian、Ubuntu、Fedora、RHEL 向けの Linux パッケージは署名付きリポジトリで提供しています。すべての Release には、macOS(Apple Silicon と Intel)、Linux(x86_64 と arm64)、FreeBSD 向けのアーカイブが付属します。すべてのインストール方法を参照してください。

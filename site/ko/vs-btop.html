gander / btop과의 비교

gander vs btop

둘 다 htop의 레이아웃을 거부합니다. 무엇으로 대체할지는 의견이 다릅니다. btop은 시스템을 그리고, gander는 프로세스를 나열합니다.

질문이 “이 시스템이 어떻게 돌아가고 있나”라면 btop을 고르세요. 질문이 “어떤 프로세스가 그렇게 하고 있나”이거나 그 답을 스크립트에서 필요로 한다면 gander를 고르세요.

설치 소스

같은 부류처럼 보이는 다른 도구

btop은 리소스 모니터입니다. CPU, 메모리, 네트워크, 디스크, 온도를 그래프와 점자 플롯으로 보여 주고, 프로세스 목록은 여러 상자 가운데 하나입니다. 하는 일은 잘하고, 대시보드가 필요하다면 맞는 답입니다.

gander는 프로세스 목록입니다. htop과 같은 부류로, 선택한 프로세스의 세부 정보를 별도 화면에서 한 열로 옮겼을 뿐입니다. 스크린샷이 설명의 전부입니다:

gander panels — 미터를 한 열로 압축
gander htop 레이아웃 (L)

한눈에 비교

ganderbtop
답하는 기본 질문어떤 프로세스시스템 상태
htop이 아닌 레이아웃panels예
htop 키 바인딩 계승예아니요
기존 htoprc 읽기예아니요
선택한 프로세스의 세부 정보가 목록 옆에예아니요
CPU / 메모리 / 네트워크 / 디스크 그래프CPU, 메모리, 디스크, 네트워크, PSI네 가지 모두, 온도까지

btop의 플랫폼 목록이 한 방향으로는 더 넓습니다. gander가 지원하지 않는 NetBSD와 OpenBSD로도 빌드됩니다. 시스템이 그쪽이라면 답은 btop이고 이 페이지는 대상이 아닙니다.

실용적인 차이는 스크립팅입니다

btop은 화면입니다. 기계가 읽을 수 있는 스냅샷을 요청하는 지원되는 방법이 없으므로, 자동화하려면 화면을 긁거나 /proc을 직접 읽어야 합니다.

gander의 배치 모드는 같은 바이너리에서 TUI를 끈 것입니다:

gander --json --limit 10                   # JSON 샘플 1회, 상위 10행
gander --sort PERCENT_MEM --limit 20       # 메모리 기준 무거운 20개
gander -F "python|node" -n 5               # 샘플 5회, 필터 적용

매일 쓰는 기능은 아닙니다. 보기만 하는 도구와 cron 잡에 넣을 수 있는 도구의 차이입니다.

설치

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # Rust가 있는 모든 플랫폼

서명된 apt, dnf 저장소와 일곱 타깃용 압축 파일은 설치 절에 있습니다.

이어서 읽기

vs htop

gander가 키 바인딩과 열의 의미를 빌려 온 도구.

vs bottom

크로스플랫폼 그래프와 위젯, 그리고 “공식 지원”의 의미.

FreeBSD에서 htop

libkvm 백엔드, 그리고 FreeBSD를 건너뛰는 대체 도구들.

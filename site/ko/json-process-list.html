스크립트를 위한 JSON 프로세스 목록

TUI가 보여 주는 수치를 샘플당 JSON 문서 하나로. cron 잡, 모니터, 그렇게 하지 않으면 고정폭 ps 출력을 파싱하게 될 모든 것을 위하여.

한 번 뽑아 쓰는 열 출력은 ps가 여전히 맞는 도구입니다. 메모리 백분율, 잘리지 않는 명령줄, 바이트 단위 크기를 데이터로 받고 싶다면 Linux, macOS, FreeBSD 모두에서 gander --json을 쓰세요. 실시간 CPU 백분율이 필요하면 같은 호출 안에서 최소 두 샘플을 받으세요. 첫 샘플에는 CPU 기준선이 없습니다.

설치 소스

대체 도구가 스크립트에 주는 것

ps는 공백으로 정렬된 열로 스냅샷 하나를 출력합니다. 그래서 모든 서버의 스크립트 절반에는, 열 이름이 바뀌는 날 깨지는 awk 호출이 들어 있습니다. CPU 수치는 프로세스의 수명 평균이지 지금 하는 일이 아니고, comm과 전체 명령줄을 잘리지 않게 함께 얻으려면 procps와 Darwin이 서로 다른 플래그를 알아야 합니다.

top에는 배치 모드(-b)가 있지만, 배치하는 것은 렌더링된 curses 화면입니다. 데이터가 아니라 화면을 긁어 온 텍스트입니다. htop에는 배치 모드가 아예 없습니다. 무엇이든 샘플 하나를 요청할 방법이 없습니다. btop도 같은 처지이고 bottom도 마찬가지입니다.

그 공백 탓에 셸 스크립트는 결국 플랫폼마다 /proc을 손으로 다시 읽게 됩니다. gander의 TUI와 배치 모드는 같은 백엔드를 읽습니다. Linux의 /proc, macOS의 sysctl/Mach/libproc, FreeBSD의 sysctl/libkvm. 스크립트가 보는 수치가 대화형 화면이 보여 주는 수치와 같습니다.

배치 모드

gander --json                       # JSON 샘플 1회 후 종료
gander --json --limit 5             # 최대 5행
gander --json --sort PERCENT_MEM    # TUI의 F6와 같은 정렬
gander --json -F "postgres|nginx"    # 고정 문자열 필터, 정규 표현식 아님
gander -n 60 -d 1000 --json         # 샘플 60개, 약 1초 간격

한 번의 호출은 프로세스 행의 JSON 배열 하나를 출력하고 종료합니다. -n N을 주면 배열 N개를 차례로 출력합니다. 문서의 스트림이므로 jq -s 'add'가 한 번의 실행을 목록 하나로 합칩니다. 정렬과 필터링은 JSON이 만들어지기 전에 일어나므로, --limit 5는 다섯 행을 출력하고 멈춥니다. 전체 표를 만든 뒤 잘라내는 방식이 아닙니다.

cpu_percent에는 프로세스의 연속된 두 샘플이 필요합니다. 호출은 항상 새 샘플러로 시작하므로 첫 샘플은 모든 행의 CPU를 0으로 보고하고, 새로 관측된 프로세스도 이후 샘플에서 0부터 시작합니다. 메모리 수치에는 이 기준선이 필요 없습니다. 스크립트나 cron 잡을 위해 CPU 샘플을 얻으려면 1초 간격으로 두 샘플을 받고 두 번째 배열만 남기세요:

gander -n 2 -d 1000 --json | jq -s '.[1]'

jq로 메모리를 가장 많이 쓰는 다섯 프로세스를 탭으로 구분해 출력:

gander --json --sort PERCENT_MEM --limit 5 |
  jq -r '.[] | [.pid, .mem_percent, .rss, .cmdline] | @tsv'

같은 행 집합을 1분 실행 동안 합쳐, 순간적으로 치솟았다 사라지는 것을 잡아냅니다:

gander -n 60 -d 1000 --json | jq -s 'add |
  group_by(.comm) | map({comm: .[0].comm, max_rss: (map(.rss) | max)}) |
  sort_by(-.max_rss) | .[0:10]'

필드

macOS에서 나온 실제 행:

{"pid":407,"ppid":1,"uid":0,"comm":"loginwindow","state":"S",
  "cpu_percent":0.00,"mem_percent":0.18,"rss":15613952,
  "vsize":446144643072,"nice":0,"priority":0,"threads":6,
  "elapsed":479475,"is_thread":false,"identity":407,
  "cmdline":"/System/Library/CoreServices/loginwindow.app/Contents/MacOS/loginwindow console",
  "memory":null}
필드의미
pid, ppid, uid커널이 보고하는 그대로의 id.
comm실행 파일의 기본 이름. TUI가 기본으로 정렬하는 열입니다.
cmdline인자를 포함한 전체 명령줄. 결코 잘리지 않습니다. ps에서는 이 필드 하나를 얻자고 싸워야 합니다.
state커널의 상태 문자. R 실행 중, S 대기 중, Z 좀비 등.
cpu_percent프로세스의 연속된 샘플 사이 구간의 CPU 사용량이지 수명 평균이 아닙니다. 이전 샘플이 있을 때까지는 0이며, 호출의 첫 샘플에 속한 모든 행도 0입니다.
mem_percent샘플 시점의 총 물리 메모리에 대한 상주 메모리 비율. 첫 샘플에서도 구할 수 있습니다.
rss, vsize상주 및 가상 크기, 바이트 단위. “아마 KB겠지”가 아닙니다. 파싱한 ps 출력을 못 믿게 만드는 단위 모호성이 바로 이것입니다.
nice, priority, threads커널이 보고하는 그대로의 스케줄링 수치.
elapsed프로세스가 시작된 이후의 초.
is_thread프로세스가 아니라 다른 프로세스의 스레드인 행은 참입니다. --threads를 주면 스레드별 행도 함께 출력됩니다.
identity행의 숫자 식별자. 프로세스 행은 PID, 스레드 행은 스레드별 ID입니다. macOS에서 PID를 공유하는 스레드를 구별합니다. 컨테이너 식별자가 아니며, 항상 존재합니다.
memory플랫폼에 따라 다른 중첩 메모리·리소스 세부 정보. macOS와 FreeBSD에서는 null입니다. Linux에서는 선택적 읽기를 요청하지 않았거나 데이터를 구할 수 없을 때 개별 값이 null입니다.

정렬에는 TUI의 열 이름을 씁니다. PERCENT_CPU, PERCENT_MEM, M_RESIDENT, PID 등입니다. JSON 키가 아니므로 rss로 정렬하려면 --sort M_RESIDENT를 쓰세요. -F는 명령줄에 대조하는 대소문자를 구분하지 않는 고정 문자열이며 |로 구분합니다. 의도적으로 정규 표현식이 아닙니다. 주기적으로 도는 필터가 문자 하나 차이로 전부 일치하게 되어서는 안 되기 때문입니다.

아닌 것

모니터링 에이전트가 아닙니다. 각 호출은 자족적입니다. 데몬도, 저장소도, 대시보드도, 의존성도 없습니다. cron 잡이 메모리 스냅샷을 위해 파일에 gander --json을 덧붙일 수는 있습니다. CPU 측정에는 위의 두 샘플 명령을 쓰세요. 파일은 계속 jq로 읽을 수 있습니다. 보존 기간과 알림이 있는 지속 수집이 필요하다면, gander가 서버를 갖추기를 기다리지 말고 이미 돌리고 있는 도구를 이 출력으로 향하게 하세요.

ps의 대체품도 아닙니다. 한 번 뽑는 열 출력, 프로세스 그룹 선택, 세션 id는 ps의 강점이고, ps로 이미 동작하는 스크립트는 바꿀 이유가 없습니다. 배치 모드는 ps가 닿지 않는 경우를 위한 것입니다. 실시간 백분율, 바이트 단위로 정확한 크기, 그리고 대화형 화면과 일치하는 수치.

설치

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # Rust가 있는 모든 플랫폼

Debian, Ubuntu, Fedora, RHEL용 Linux 패키지는 서명된 저장소에서 제공하고, 모든 Release에 macOS(Apple Silicon 및 Intel), Linux(x86_64 및 arm64), FreeBSD용 압축 파일이 포함됩니다. 모든 설치 방법을 보세요.

이어서 읽기

vs htop

같은 키와 데이터, 표 옆의 상세 정보 패널.

vs btop

자체 레이아웃을 가진 그래픽 모니터. gander와의 차이점.

macOS에서 htop

libproc, sysctl, Mach이 프로세스 뷰어에 주는 것과 주지 않는 것.

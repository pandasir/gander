gander / FreeBSD 편

FreeBSD에서의 프로세스 뷰어

FreeBSD는 새 터미널 프로세스 뷰어가 드물어지는 지점입니다. 데이터를 얻기 어려워서가 아니라, 그곳에서 테스트하는 프로젝트가 적기 때문입니다.

htop은 오래전부터 FreeBSD를 지원하고, gander는 CI의 실제 FreeBSD 커널에서 검증되는 전용 sysctl/libkvm 백엔드를 갖추고 있습니다. FreeBSD에서 새 도구를 고른다면 플랫폼 지원 행이 곧 결정인 경우가 많습니다.

도구의 순위는 아닙니다. bottom은 좋은 프로그램이고, 자신의 FreeBSD 지원 수준을 분명히 말합니다. 요점은 더 좁습니다. FreeBSD에서는 무엇보다 이 행을 먼저 확인해야 합니다. 컴파일은 되지만 플랫폼에서 검증되지 않은 뷰어는 결국 빠진 값이 아니라 틀린 값을 보여 주기 때문입니다.

gander가 FreeBSD에서 읽는 것

백엔드는 두 인터페이스를 씁니다. sysctl이 프로세스 표와 시스템 수치를 공급하고, libkvm(kvm_getswapinfo, devstat_getdevs)이 sysctl이 노출하지 않는 부분을 채웁니다.

수치출처
프로세스 목록sysctl(KERN_PROC_PROC) → kinfo_proc[]
CPU 시간, 시작 시간ki_runtime (마이크로초), ki_start
상주 및 가상 크기ki_rssize (페이지), ki_size (바이트)
상태 문자ki_stat와 ki_tdflags/ki_slptime
명령줄, 환경sysctl(KERN_PROC_ARGS), KERN_PROC_ENV
실행 파일, cwdKERN_PROC_PATHNAME, KERN_PROC_CWD
열린 파일KERN_PROC_FILEDESC
코어별 CPUkern.cp_times
메모리vm.stats.vm.v_*와 v_page_count
스왑kvm_getswapinfo(3)
디스크 처리량devstat_getdevs(3)
네트워크 처리량sysctl(NET_RT_IFLIST)
CPU 선호도cpuset_getaffinity / cpuset_setaffinity

그 행마다 개발 중에, 다른 도구와의 비교로만 잡을 수 있었던 버그가 생겼습니다. 알아 둘 만한 것들 몇 가지:

  • ki_runtime은 마이크로초입니다. 반면 Linux와 macOS의 모든 CPU 시간 필드는 틱 카운터입니다. 이를 HZ 제수로 나누면 네 자릿수나 벗어난 백분율이 나옵니다.
  • ki_rssize는 페이지이고 ki_size는 바이트입니다. 짝처럼 보이지만 짝이 아닙니다. 페이지 크기를 잊으면 1.2 GB 프로세스를 300 MB로 보고하는데, 리뷰를 통과할 만큼 그럴듯한 수치입니다.
  • ki_stat은 상태 문자가 아닙니다. SSLEEP은 ki_tdflags & TDF_SINTR와 ki_slptime에 따라 셋으로 갈라지고, 이를 산술적으로 대응시키면 새로 시작한 프로세스가 I로, 잠긴 프로세스가 X로 표시됩니다.
  • kvm_getswapinfo는 페이지를 보고합니다. htop 자신의 FreeBSD 백엔드는 페이지 크기 대신 1024를 곱하는데, 그러면 1 GiB 스왑 파일을 4 MiB로 보고하면서 단위는 바이트라고 표시합니다. gander는 swapinfo(8)과 같은 방식으로 계산합니다.
  • hw.physmem은 VM이 관리하는 메모리보다 큽니다. 이를 메모리 막대의 분모로 쓰면 막대가 영영 가득 차지 않는데, 정말로 메모리가 부족한 시스템에서는 이것이 렌더링 버그로 읽힙니다.

FreeBSD에 없는 것, 그리고 gander의 표시 방식

macOS와 같은 규칙입니다. -만 렌더링하게 될 열은 열 목록에서 빠지고, 미터는 n/a here를 표시하며 제자리에 남아 시스템 사이를 옮겨 다니는 설정 파일도 여전히 불러올 수 있게 합니다.

FreeBSD에서
PSS / EPSSsmaps_rollup 없음, 제외
PSI, zram, zswap, HugePages미터에 n/a here 표시
컨테이너 열jail은 컨테이너가 아님, 제외
GPU 열drm-usage-stats 없음, 제외
지연 통계TASKSTATS는 Linux 전용, 제외
I/O 우선순위 (i)ioprio_set 없음, 패널이 안내
파일 잠금 패널 (x)잠금 테이블 없음, lsof 안내
CPU 선호도, 환경, 열린 파일지원
호스트 전체 디스크 처리량지원, 두 수치를 모두 갖춘 유일한 플랫폼

jail은 흥미로운 생략입니다. kinfo_proc.ki_jid는 읽어 두었고 사용할 수 있지만, 이를 렌더링하는 곳은 없습니다. jail은 커널을 공유하고 이미지 레이어도, 작은 정수 너머의 식별자도 없으므로 CONTAINER로 표기하는 것은 거짓 등식이 됩니다. 흔한 경우인 jid 0은 호스트라서, 이 열은 몇 개의 예외를 제외하면 0의 나열이 될 것입니다.

테스트 방법

FreeBSD에는 GitHub 호스티드 러너가 없으므로 두 가지 방법으로 확인합니다. 모든 push에서 crate 전체를 x86_64-unknown-freebsd로 크로스컴파일하고, QEMU 위의 FreeBSD 14 VM 안에서 전체 테스트를 실행합니다. 중요한 것은 VM 잡입니다. 라이브 테스트가 게스트 안에서 gander의 수치를 ps(1), sysctl(8), swapinfo(8), netstat(1)과 비교합니다. 위에 나열한 버그 대부분은 크로스컴파일로는 보이지 않는 것들입니다.

각 플랫폼에서 의도적으로 빠진 행까지 모두 담은 전체 매트릭스는 docs/PORTABILITY.md에 있습니다.

FreeBSD에 설치

모든 Release에 x86_64-unknown-freebsd 압축 파일과 그 옆의 .sha256 파일이 포함됩니다:

tar -xzf gander-<version>-x86_64-unknown-freebsd.tar.gz
./gander-<version>-x86_64-unknown-freebsd/gander

Rust 툴체인이 있다면:

cargo install gander-bin

현재 압축 파일은 Release에서, 모든 설치 방법은 설치 절에서 확인하세요.

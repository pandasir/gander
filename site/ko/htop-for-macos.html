gander / macOS 편

macOS에서의 프로세스 뷰어

htop은 macOS에서 동작합니다. 사람을 헷갈리게 하는 것은 htop이 아닙니다. Linux에서 익숙한 여러 수치에 macOS에 상응하는 것이 없고, 그런 수치를 그래도 보여 주는 뷰어는 추측을 표시하고 있다는 점입니다.

이 페이지는 목록입니다. macOS가 프로세스 뷰어에 알려 주는 것, 주지 않는 것, 그리고 각 공백에 대해 gander가 취하는 처리입니다. 같은 인터페이스를 읽으므로 htop에도 그대로 적용됩니다.

macOS가 주는 것

htop 프로세스 표의 거의 모든 것은 세 곳에서 나오고, 세 곳 모두 macOS에서 동작합니다:

수치출처
프로세스 목록proc_listallpids와 PROC_PIDTASKALLINFO
명령줄sysctl(KERN_PROCARGS2)
실행 파일 경로proc_pidpath
작업 디렉터리proc_pidinfo(PROC_PIDVNODEPATHINFO)
스레드PROC_PIDLISTTHREADS + PROC_PIDTHREADINFO
메모리 총량, 스왑host_statistics64, hw.memsize, sysctl(vm.swapusage)
코어별 CPUhost_processor_info
네트워크 처리량sysctl(NET_RT_IFLIST2)

그러니 htop이 “macOS에서는 제대로 동작하지 않는다”는 흔한 주장은 틀렸습니다. 동작합니다. 흥미로운 부분은 두 번째 표입니다.

macOS가 주지 않는 것

여기의 모든 행은 Darwin에 대응물이 없는 Linux 전용 메커니즘입니다.

macOS에서의 gander
프로세스별 PSS / EPSS열 자체가 없음, - 아님
PSI 압력 미터미터에 n/a here 표시
Zram / Zswap / HugePages미터에 n/a here 표시
컨테이너 / cgroup 식별 정보cgroup 개념 없음, 열 제외
CPU 지연 통계열 제외
I/O 우선순위 (i)ioprio_set 없음, 패널이 그렇게 안내
GPU 열IOKit 필요, 제외
호스트 전체 디스크 처리량미터에 n/a here 표시
CPU 선호도 편집힌트만 제공

중요한 구분은 없는 열과 -를 렌더링하는 열 사이의 차이입니다. 열의 -는 “지금 이 프로세스에는 해당 값이 없다”로 읽힙니다. 없는 열은 “이 시스템에는 그 개념 자체가 없다”로 읽힙니다. gander는 macOS에서 해당 열을 설정 화면에서 아예 빼고, 미터는 제자리에 두고 n/a here를 표시합니다. Linux에서 작성한 설정 파일도 Mac에서 불러와야 하고, 사라진 미터는 정직한 설정이 아니라 깨진 설정이 되기 때문입니다.

메모리: 버그로 오해받는 수치

macOS의 메모리 계산 방식은 Linux의 것과 다릅니다. 한쪽을 다른 쪽에 대응해 보여 주는 뷰어는 눈에 보일 만큼 틀린 수치를 냅니다. vm_statistics64는 서로 겹치는 두 부류의 카운터를 노출합니다. 사용 용도 기준(active, inactive, wire, compressor, free, speculative)과 백킹 스토어 기준(internal, external)이며, 부류를 넘어 더하면 이중 계산이 됩니다. gander는 백킹 스토어 부류에 이 부류가 다루지 않는 두 페이지 범주를 더해 수치를 만듭니다:

used      = (internal - purgeable) + wired + compressed
available = total - used

htop이 출력하는 것과 같은 수치이고, 같은 방식으로 도출되며, Activity Monitor와 top이 보고하는 것과도 같은 수치입니다. Mac에서는 gander와 htop이 서로 일치합니다. 둘 다 일치하지 않는 것은 vm_stat에서 계산한 성급한 total - free이며, 이 비교가 어느 쪽 도구든 틀리게 보이게 만듭니다.

inactive와 speculative는 사용량이 아니라 캐시로 세세요. 일주일 동안 켜져 있던 시스템이 inactive가 크다는 이유로 메모리가 부족한 게 아닙니다. 회수 가능한 영역입니다.

Mac에서 gander와 htop이 다른 점

수치는 일치하지만 화면은 다릅니다. htop의 세부 정보 패널은 전체 화면 모드입니다. 환경 변수는 e, 열린 파일은 l, 시스템 콜은 s이며 각각 프로세스 목록을 대체하고, 돌아오면 자리를 다시 찾아야 합니다. gander는 선택한 프로세스의 명령줄, 상태, 메모리, 실행 시간을 표 옆의 한 열에 유지하므로 목록은 제자리에 있습니다.

키 바인딩도 같고 htoprc 가져오기도 같습니다. 원래 목적이 htop 레이아웃이었다면 L로 얻을 수 있습니다. 달라지는 키는 vs htop을 보세요.

macOS에 설치

brew install pandasir/tap/gander

# 또는 Rust 툴체인으로
cargo install gander-bin

Apple Silicon과 Intel 양쪽용으로 미리 빌드된 압축 파일도 Release에 있습니다.

macOS 라이브 테스트는 실제 프로세스 표를 읽으므로, 테스트 스위트는 제한된 샌드박스 밖에서 실행해야 할 수 있습니다. 세 플랫폼 모두의 백엔드 비교는 docs/PORTABILITY.md에 있습니다.

gander / htop과의 비교

gander vs htop

같은 프로세스 데이터, 같은 키 바인딩입니다. 다른 점은 선택한 프로세스의 세부 정보가 사는 위치입니다. 키 입력 한 번 거리가 아니라 표 바로 옆에 있습니다.

모든 배포판에 기본으로 들어 있는 도구면 충분하다면 htop을 쓰세요. htop 키에 이미 익숙하고 표를 포기하지 않고 상세 정보 패널을 원한다면 gander를 쓰세요.

설치 소스

일하는 방식을 바꾸는 단 하나의 차이

htop은 모든 프로세스를 한꺼번에 보여 줌으로써 “지금 뭐가 돌고 있나”에 답하고, “그 프로세스는 뭘 하고 있나”는 다른 화면에서 답합니다. 구버전의 info 패널, 신버전의 별도 뷰입니다. 어느 쪽이든 읽는 동안 표는 사라집니다.

gander는 둘 다 화면에 둡니다. 상세 정보 패널은 표 옆의 한 열이고 커서를 따라가므로, 목록을 내려가면 프로세스마다 키를 누르는 대신 세부 정보가 다시 읽힙니다. 넓은 터미널에서는 놀고 있는 공간이 일을 하는 것이고, 좁은 터미널에서는 겹쳐 보이는 대신 레이아웃이 단순해집니다.

htop의 배치가 더 낫다면 L을 누르세요. 전체 너비 레이아웃이 내장되어 있고 선택은 기억됩니다.

대시(—)는 해당 사항 없음입니다. htop은 정의상 htop의 키 바인딩을 쓰고 htop의 설정을 읽습니다.

이 표의 대부분은 htop이 기준이고, gander는 열의 의미와 키 바인딩을 htop에서 의도적으로 가져왔습니다. gander가 단순히 “htop에 패널을 얹은 것”이 아닌 행은 마지막 세 개입니다. 배치 모드, Linux 전용 추가 열, 그리고 htop에는 상세 정보 패널에 해당하는 것이 없다는 사실입니다.

설정을 다시 하지 않고 전환하기

htop은 설정을 htoprc에 저장합니다. gander는 이 파일을 읽고 자체 TOML로 변환해 기록하므로, 여러 해에 걸쳐 다듬은 열 구성과 정렬 순서가 그대로 넘어옵니다:

gander --import-htoprc ~/.config/htop/htoprc --save

--save 없이는 가져오기가 드라이런으로 동작하며 무엇을 바꿀지 출력만 합니다. htoprc는 수정되지 않으므로 htop은 그대로 동작하고, 두 도구를 나란히 비교할 수 있습니다.

가져오기는 htop의 1부터 시작하는 열 id를 처리합니다. 성급한 변환이 틀어지는 지점이 바로 여기입니다. gander에 대응하는 설정이 없으면 조용히 버리는 대신 알려 줍니다.

다른 키

htop 함수 표시줄의 나머지 키는 htop이 둔 자리에 그대로 있습니다. 다음은 다릅니다:

Ihtop에서는 정렬 순서를 반전합니다. gander에서는 선택한 헤더 미터의 표시 모드를 전환합니다. 정렬 변경에는 F6 / < >를 사용하세요.
Lpanels와 htop 레이아웃 사이를 전환합니다. htop에는 없는 키입니다.
+ / -샘플링 속도를 높이거나 낮춥니다.
Shift+Left / Shift+Right헤더 미터 커서를 이동합니다.

배치 모드 플래그를 포함한 전체 키 맵은 docs/KEYS.md에 있습니다.

설치

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # Rust가 있는 모든 플랫폼

Debian, Ubuntu, Fedora, RHEL용 Linux 패키지는 서명된 저장소에서 제공하고, 모든 Release에 macOS(Apple Silicon 및 Intel), Linux(x86_64 및 arm64), FreeBSD용 압축 파일이 포함됩니다. 모든 설치 방법을 보세요.

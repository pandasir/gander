gander / 与 bottom 对比

gander vs bottom

三者中最接近的一组对比:都是 Rust,都覆盖 Linux、macOS 和 FreeBSD,都拒绝了 htop 的布局。差别在屏幕是拿来做什么的。

bottom 给你一块自己排布的小部件仪表盘;gander 给你 htop 的进程列表,细节挪到同一块屏幕上。要图表和可配置性,bottom 走得更远;要 htop 的肌肉记忆和可脚本化的输出,选 gander。

FreeBSD:「能编译」不等于「受支持」

bottom 的 README 对此写得很明白。它的官方平台是 macOS、Linux 和 Windows;FreeBSD x86_64 出现在第二张列表里,原话是:

可能没有在 CI 中测试构建或测试是否通过。稳定版发布前可能未经维护者适当测试。可能只获得有限支持,例如缺少功能,或存在可能不被修复的 bug。

bottom 在描述自己的边界,这也是本项目努力做的事。但这意味着 FreeBSD 不是一个你可以放心依赖 bottom 的平台。

gander 有专门的 FreeBSD 后端,读取 sysctl 和 libkvm;还有一条 CI 任务,在 QEMU 的 FreeBSD 14 虚拟机里跑完整测试套件,把 gander 的数值与虚拟机内的 ps(1)、sysctl(8)、swapinfo(8) 和 netstat(1) 逐一对照。在 FreeBSD 上确实缺失的能力都列了出来,不做暗示:没有容器列、没有 PSS、没有 GPU 列、没有磁盘吞吐 meter。见 FreeBSD 上的 htop。

如果你用 FreeBSD,这就是本页最实在的差别。

脚本:gander 有批处理模式

bottom 没有任何可供脚本调用的东西:要自动采集,你得自己去读 /proc(或等价物)。这没问题——直到你想拿到和 TUI 一样的口径。

gander 的批处理模式是同一个二进制、关掉界面,脚本看到的数字就是屏幕本来会画的数字:

gander --json --limit 10
gander --sort PERCENT_MEM --limit 20
gander -F "python|node" -n 5

退出码是有含义的:扫描失败会返回非零退出码,而不是一个空数组。

从 htop 过来

两者之中只有 gander 读 htoprc。如果你在 htop 里攒了多年的列和排序,这是你最先注意到的差别:

gander --import-htoprc ~/.config/htop/htoprc --save

不带 --save 时导入是试运行,htoprc 永远不会被改动。有差别的按键见 vs htop。

安装

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # 任何有 Rust 的平台

签名 apt 和 dnf 软件源,以及包含 x86_64-unknown-freebsd 在内的压缩包,都在安装一节。

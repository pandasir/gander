gander0.6.7

一个用 Rust 编写的跨平台交互式进程查看器,支持 Linux、macOS 和 FreeBSD。

它读取的数据和 htop 相同,沿用 htop 的按键,并把选中进程的细节放在列表旁边;htop 把它们放在另一块屏幕上。

下载 GitHub 源码 安装

它能做什么

gander 显示系统里正在运行什么、各自消耗多少。它支持 Linux、macOS 和 FreeBSD,沿用 htop 的大部分按键,已经在你手指上的键继续有效。

检视面板跟着光标走

选中一行,右侧面板随即填入:命令行、状态、内存、运行时间、用户、线程数。

采样不在渲染路径上

后台线程负责采样,渲染端只读快照。机器最忙、正是你盯着看的时候,表格也不会卡顿。

htop 的设置跟着走

--import-htoprc 读取现有的 htoprc,--save 把它写成 gander 自己的 TOML。你调好的列和排序都搬得过来。

不开 TUI 也能用

--json、-n、--sort、--filter 和 --limit 输出进程行后直接退出,不用再从 curses 屏幕里抠数据。字段说明和 jq 示例见批处理模式页。

Linux 上能读的更多

PSS/EPSS、PSI、zram/zswap、GPU、延迟统计和容器识别可作为可选列或表头 meter,从 /proc 和 /sys 读取。

不用装 ncurses

渲染用 ratatui 和 crossterm。构建前不需要装开发头文件,也没有要链接的终端库。

同一台机器的三种看法

panels —— 默认布局 查看原图(新标签页)
t —— 树状视图 查看原图(新标签页)
L —— htop 布局 查看原图(新标签页)

和其他进程查看器比起来怎么样

ganderhtopbtopbottom
Linux / macOS / FreeBSD三个平台,全部支持三个平台,全部支持三个平台,CI 中构建FreeBSD 非官方
沿用 htop 的按键是—否否
导入现有的 htoprc是—否否
选中进程留在屏幕上,细节可见是否否否
不是 htop 的那种布局panels—有有
--json 批处理模式有无无无

「—」表示不适用——htop 的按键和 htoprc 本来就是它自己的。

日常使用里真正要紧的是关于选中进程的那一行。htop、btop 和 bottom 回答「现在在跑什么」的方式是把所有进程铺开,你关心的那个进程的细节要么在另一个界面,要么没有。gander 把检视面板放在表格旁边,选中一行,答案就在眼前,不用离开列表。

更长的对比,每个工具一页:gander vs htop、gander vs btop、gander vs bottom。平台相关:macOS 上、FreeBSD 上。

安装

macOS(Homebrew)

brew install pandasir/tap/gander

任何有 Rust 的平台

cargo install gander-bin   # 安装后的命令是 `gander`

Arch Linux

git clone https://github.com/pandasir/gander
cd gander/packaging/aur && makepkg -si

Debian、Ubuntu

curl -fsSL https://pandasir.github.io/gander/gander.gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/gander.gpg
echo "deb [signed-by=/usr/share/keyrings/gander.gpg] https://pandasir.github.io/gander stable main" \
  | sudo tee /etc/apt/sources.list.d/gander.list
sudo apt update && sudo apt install gander

Fedora、RHEL

sudo rpm --import https://pandasir.github.io/gander/RPM-GPG-KEY-gander
sudo curl -fsSL https://pandasir.github.io/gander/gander.repo \
  -o /etc/yum.repos.d/gander.repo
sudo dnf install gander

预编译压缩包

每个 Release 都附带 macOS(Apple Silicon 和 Intel)、Linux(x86_64 和 arm64,glibc 与静态 musl)以及 FreeBSD 的 .tar.gz 压缩包,旁边各有 .sha256 文件。见 GitHub Releases。

从源码构建

需要 Rust 1.89 或更新版本。

git clone https://github.com/pandasir/gander
cd gander
cargo install --locked --path crates/bin

使用

gander                                     # 交互式 TUI
gander --delay 500                         # 每 500 毫秒采样一次
gander -n 5 -d 1000                        # 输出 5 次文本采样
gander --json --limit 10                   # 输出一次 JSON
gander --sort PERCENT_MEM --limit 20       # 按内存排序取前 20
gander -F "python|node"                    # 过滤命令行
gander --import-htoprc ~/.config/htop/htoprc --save

过滤词是大小写不敏感的固定字符串,用 | 分隔;不是正则表达式。全部选项见 gander --help。

常见问题

gander 能替代 htop 吗?

能,也不能。它读的是同一份 /proc 数据,按键也照 htop 摆,你现在的工作方式不用改;--import-htoprc 能把你的 htop 设置直接搬过来。但默认布局刻意不是 htop 那种,因为「全宽表格 + 第二个界面看细节」并不是读进程列表的唯一方式。

gander 支持 Windows 吗?

不支持。三个后端分别是 /proc(Linux)、sysctl/Mach/libproc(macOS)和 sysctl/libkvm(FreeBSD)。没有 Windows 后端;依赖 Linux 内核接口的列(PSS、PSI、zram、延迟统计、容器)也只在 Linux 上有。

crates.io 上的包为什么叫 gander-bin?

因为 crates.io 上的 gander 是一个无关的、早已 yank 的包。装完命令仍然是 gander。

为什么不用 ncurses?

渲染用的是 ratatui 和 crossterm,编译前不需要装 ncurses 开发头文件。

能用在脚本里吗?

能。gander --json、-n、--sort、--filter 和 --limit 不启动 TUI,直接输出每个进程一行。字段说明和 jq 示例在 JSON 进程列表页。

gander 用什么许可证?

GPL-2.0-or-later。gander 的行为、按键绑定和列语义取自 htop;请保持许可证兼容并注明出处。

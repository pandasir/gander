gander / 与 btop 对比

gander vs btop

两者都拒绝了 htop 的布局,但在用什么取代上各执一词:btop 画机器,gander 列进程。

问「这台机器怎么样」,选 btop。问「是哪个进程干的」,选 gander——或者,当你想在脚本里拿到这个答案时,也选 gander。

安装 源码

看起来同类,其实是不同的工具

btop 是资源监控器:CPU、内存、网络、磁盘和温度都以图表和盲文点阵呈现,进程列表只是其中一格。它把自己做的事做得很好;要仪表盘,它就是正确答案。

gander 是进程列表——和 htop 同属一类——把选中进程的细节从单独的界面挪进旁边一列。截图就是全部论证:

gander panels —— 仪表压进一列

btop 的平台列表有一个方向更宽——它还能为 NetBSD 和 OpenBSD 构建,gander 不能。如果你用的是那些系统,选 btop,这页不是为你写的。

脚本的差别才是实用的差别

btop 是一块屏幕。没有受支持的方式向它要一份机器可读的快照,自动化只能要么抓屏幕,要么自己去读 /proc。

gander 的批处理模式是同一个二进制,关掉 TUI:

gander --json --limit 10                   # 一次 JSON 采样,前 10 行
gander --sort PERCENT_MEM --limit 20       # 内存最高的 20 个
gander -F "python|node" -n 5               # 5 次采样,带过滤

这不是天天用的功能。它是「用眼睛看的工具」和「能塞进 cron 的工具」之间的差别。

安装

brew install pandasir/tap/gander     # macOS
cargo install gander-bin             # 任何有 Rust 的平台

签名 apt 和 dnf 软件源,外加七个目标的压缩包,都在安装一节。

### 阻塞原因

FreeBSD Bugzilla **关掉了自助注册**。现在的流程是人工的：

> To create a FreeBSD Bugzilla account, you need to email the maintainer of this
> Bugzilla installation at bugmeister@FreeBSD.org, providing a legitimate email
> address. ... Unfortunately, it became necessary to disable the previous
> auto-account-creation method due to the rise of AI-generated spam.

**已经开始**：2026-10-23 向 bugmeister@FreeBSD.org 发了申请邮件，等对方开通。
开通后登录邮箱会收到确认信，**收到确认信之前无法登录**。

### 账号开通后要做的事

只有一步，但顺序不能错：

1. 打开 <https://bugs.freebsd.org/submit/>
2. Product 选 **Ports & Packages**
3. Component 选 **Individual Port(s)**
4. Summary 填：

   ```
   [NEW PORT] sysutils/gander Interactive process viewer for the terminal
   ```

5. 附件上传 **`packaging/freebsd/gander.sysutils.diff`**（仓库里已经生成的，
   不需要重新构建）
6. 正文写几句：gander 是什么、FreeBSD 后端读 `sysctl`/`libkvm`/`kinfo_proc`
   所以不需要挂载 procfs、以及它和 htop 的差别是布局而不是数据

审核周期官方说法是「几天到几个月」。**在 committer 接手之前不要改 README。**

### 提交之后要改的文档

`packaging/check-channels.sh` 有一条检查会**主动失败**来提醒这件事：一旦 README
或站点上出现 `pkg install gander` 而 `freshports.org/sysutils/gander` 还是 404,
脚本就报错。所以不需要靠记忆。

真正要在 PR 被接受后改的地方：

- [ ] `README.md` 的 **Package managers** 表格加一行
      `| FreeBSD | pkg install gander |`，位置按字母序放在 Homebrew 之后
- [ ] `README.zh-CN.md`、`README.ja.md`、`README.ko.md` 同表格加同一行
- [ ] `site/index.html` 的安装区块加同一条命令
- [ ] 跑 `packaging/check-channels.sh`，确认它从「没有包也没有文档」变成
      「有包也有文档」
- [ ] 下次发版时把 `packaging/freebsd/Makefile` 的 `DISTVERSION` 和
      `distinfo` 一起更新，并重新生成 `gander.sysutils.diff`
      （`packaging/freebsd/gen-port.sh` 会做这件事，但它只能在 FreeBSD 上跑）

### 之后每次发版都要做的

port 一旦进了 ports 树，就变成**别人**的维护负担。发版时：

```bash
# 在 FreeBSD 上（或跑 .github/workflows/freebsd-port.yml）
sh packaging/freebsd/gen-port.sh /tmp/ports
```

然后把新的 `distinfo` 和 `DISTVERSION` 作为**单独的补丁**发给
`bugmeister@FreeBSD.org` 或对应 port 的 maintainer，而不是等别人发现升级失败。
